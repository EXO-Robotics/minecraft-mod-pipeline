# AI processing policy

The private GitHub repository is the authoritative (“gold”) copy of this
project. A local clone is the normal working copy.

## Standing OpenAI Codex authorization

The project owner grants standing authorization for OpenAI Codex to receive and
process the authorized repository data listed below when necessary to perform
work explicitly requested in an owner-controlled Codex task. This authorization
applies to the Codex desktop app, Codex CLI, OpenAI-managed Codex cloud tasks,
native Codex subagents, and model-backed Codex subprocesses operating within
the same requested task.

Authorized repository data:

- tracked source code, tests, schemas, documentation, and project configuration;
- intentional working-tree diffs selected for the requested task;
- build, test, validation, packaging, and Git metadata needed to complete or
  verify the requested task;
- generated artifacts whose disclosure is necessary for the requested task and
  whose rights and provenance records permit that processing.

Authorized purposes include repository inspection, implementation, generation,
testing, debugging, review, packaging, and task-scoped Codex delegation. This is
standing authorization, so a new owner confirmation is not required solely
because a later requested Codex task needs to send authorized repository data
to an OpenAI Codex execution context.

This authorization does not make the private repository public and does not
authorize model-training opt-in, public sharing, release, publication, or
disclosure to unrelated third-party model providers, services, or people. Grok
and other non-OpenAI providers require separately scoped authorization.

Excluded data remains excluded unless the owner separately authorizes it:

- credentials, access tokens, private keys, cookies, and authentication state;
- evidence-vault material and hidden clean-room test material;
- licensed or third-party source restricted to analysis-only handling;
- personal information and unrelated private files;
- unrelated repository history, caches, editor indexes, and environment files;
- artifacts whose rights ledger prohibits the intended processing.

The narrowest practical task context should be sent. Clean-room lane boundaries,
rights restrictions, and production-agent source exclusions continue to apply.
This authorization may be revoked or narrowed by the project owner at any time.

The MIT license governs use and redistribution of the project’s licensed
software. It does not itself authorize access to private systems or override
the disclosure boundaries above. Repository policy also cannot disable
platform-enforced authentication, sandbox, network, or high-risk-action
approval prompts.
