# Produce a Golden Blockbench Asset

Require a standardized assignment for role `visual_producer`, skill
`produce-golden-blockbench-asset`, and lane `PRODUCTION`. Validate it with
`$translate-java-mods-to-bedrock`'s
role-contract validator. `requires_activation_attestation` must be true.

Operate only inside the assigned visual-production lane. The typed visual
contract, class profile, proof-render contract, and production-facing Bedrock
interfaces are the sole authority.

## Verify the packet and boundary

Require the actual visual-authoring process to run through the recorded
production sandbox and emit a minimal activation attestation. Repairs require a fresh attestation.

Require one hash-bound assignment packet containing:

- Lane root, allowed reads/writes, prohibited paths, and stop states.
- Baseline, sanitized visual contract, class profile, and interface hashes.
- Original identity allocation and BP/RP binding points.
- Native round-trip, proof, heuristic, packaging, and freeze deliverables.
- Exact clip and proof-view inventories, tool versions/commands, output roots,
  BDS targets, and canonical archive rules.

Prove control references, Java evidence, private oracle cases, hidden canaries,
shared caches, and source-only identifiers are absent or denied. Do not search
for the reference asset or ask for source-specific clarification.

## Build from the typed contract

1. Choose an original shape grammar that satisfies the role and prohibited-cue
   constraints.
2. Stay within scale, collision, selection, visible-bounds, cube, bone,
   locator, texture, animation, controller, particle, and spawn budgets.
3. Use semantic bone and locator roles with original production identifiers.
4. Put pivots at functional joints and author motion from the new proportions.
5. Create original texture regions, palette, markings, icons, and feedback.
6. Implement only approved gameplay-visible states and animation events.
7. Where assigned, bind original localized feedback, bounded particles, and
   audio cues; record their event IDs, simultaneous caps, and missing-resource
   behavior.

Never imitate an unknown source or reuse another validation creature as a shape,
rig, palette, timing, or presentation template.

## Preserve native Blockbench integrity

- Store nested outliner groups as native nested group objects, preserve
  locators as native locator elements, and reject flattened UUID-only
  hierarchies.
- Recursively validate references and cycles.
- For representative assets, perform an actual Blockbench
  open/save/reopen/native-export round trip.
- Report static shape, UI roundtrip, native export, Bedrock rendering, and
  physical PS4 rendering as five separate evidence claims.

- Use RFC 4122-shaped UUIDs for elements, groups, animations, animators, and
  keyframes.
- Resolve every outliner, element, animator, and keyframe link.
- Bind textured cube faces to the declared embedded or project texture.
- Reopen, save, reopen, and export through native Blockbench codecs.
- Require zero warnings and exact model identity in the native capture.
- Show every required clip and actual keyframes in the timeline capture.
- Compare native export counts and required locators with the editable
  production `.bbmodel`.

Keep editable source, runtime exports, deterministic generated proofs, and
native UI captures in separate inventories. Native UI captures are evidence,
not deterministic build outputs.

## Produce fixed proofs

Use the packet's exact camera, projection, lighting, background, resolution,
pose, filename, and `source_type`. Include the required orthographic,
three-quarter, player-scale, neutral, locomotion-contact, feature-action,
texture, atlas-underlay UV, and silhouette-only views.

Require a hash-bound proof inventory with an exact count; Golden validation
creatures normally use 16 views. Do not silently drop or add views.

A deterministic renderer must use runtime pivots, rotations, animation poses,
and atlas-informed face material sampling. Do not label it a Blockbench render.
Do not substitute a shaded render for a true silhouette sheet.

## Validate and self-critique

Run production-local:

- `.bbmodel`, hierarchy, pivot, locator, UV, texture, geometry, animation,
  controller, render binding, collision, selection, and bounds checks.
- Artifact-derived silhouette, contrast, palette, uniformity, texel-density,
  repetition, thin-feature, ground-contact, foot-slide, clipping, first-frame,
  loop-seam, transition, and state-differentiation heuristics.
- Cycle 1 construction/rig/animation/proof critique.
- Cycle 2 silhouette/material/readability/originality self-review.
- Static Bedrock, Creator Tools, provenance, deterministic two-build, and
  production-local BDS checks permitted by the packet.
- Presentation bindings for localization, icons, audio, particles, and
  active/inactive/error states when assigned.

For asset-only packs set `require_script_runtime: false`; never create a fake
script marker. When the packet calls for full server qualification, produce
separate Stable and Preview receipts. State that BDS proves only the exercised
pack/entity load, server probes, stress, cleanup, and restart.

Use one immediate creator-project texture root with feature-local `entity/` and
`items/` descendants. Validate manifest UUID/dependency bindings,
`format_version`, `min_engine_version`, and the packet's exact cooperative
creator-project hierarchy.

Build canonical archives with stable lexicographic entry order, normalized file
modes, and the packet's fixed timestamp, normally 1980-01-01. Require build-one
and build-two hashes to match exactly.

Cover every file in provenance with path, purpose, role, creation time, contract
and interface hashes, artifact class, source-expression access `NONE`, reused
baseline component, originality status, and generated-from relationship. Bind
all validation and proof receipts to the candidate commit and package hash.

## Freeze for independent audit

Require no unresolved high or material medium finding, every public art category
at least 70, weighted score at least 80, deterministic export/package hashes,
and a clean candidate commit. Return `CANDIDATE_READY_FOR_VISUAL_AUDIT`.

For a portfolio assignment, return an independent score and promotion decision
for every asset. Never average a failing asset into a passing batch. Preserve
unpromoted assets as functional prototypes or backlog.

Do not claim independent originality, semantic preservation, client rendering,
controller behavior, Realm, split screen, physical PS4, Marketplace, or release
proof. Repairs received later must use opaque product findings only and create a
new candidate commit and package hash.

Use controlled stops including `PRODUCTION_INPUT_INTEGRITY_FAILED`,
`PRODUCTION_ISOLATION_INVALIDATED`, `VISUAL_CONTRACT_INCOMPLETE`,
`NATIVE_ROUNDTRIP_FAILED`, `DETERMINISTIC_EXPORT_FAILED`,
`ASSET_VALIDATION_FAILED`, and `CANDIDATE_FREEZE_FAILED`.
