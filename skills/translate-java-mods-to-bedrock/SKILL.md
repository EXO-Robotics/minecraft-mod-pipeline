# Translate Java mods to Bedrock

Reconstruct selected player-facing functionality as an original additive
Bedrock add-on. Preserve vanilla Minecraft. Do not copy Java implementation or
protected expression, and do not treat the result as a standalone game.

## Route the work

Prefer the narrow role skill over repeating this campaign guide:

- Campaign control and scaling: `$oversee-java-to-bedrock-factory`
- Intake and task separation: `$make-java-to-bedrock-task-packs`
- Mailbox/recovery: `$operate-bedrock-factory-mailbox`
- Isolated pack production/repair: `$work-bedrock-factory-pack`
- T1 and BDS qualification: `$test-bedrock-factory-pack`
- Instrumented/protocol observation: `$observe-bedrock-factory-pack`
- Independent T10 audit: `$audit-bedrock-factory-pack`
- T2/shared-runtime integration: `$integrate-bedrock-factory-pack`
- Detailed evidence/control/feature roles: use the installed analysis,
  sanitization, clean-room production, subsystem integration, visual, and
  portfolio-audit skills named in `references/subagent-orchestration.md`.

Give each role one hash-bound assignment, one lane, one writable scope, one
completion condition, and only the inputs it may know. Keep mutable campaign
facts in assignments and repositories, never in this skill.

## Core flow

1. Confirm authority to inspect supplied Java material. Record analysis,
   derivative, reuse, redistribution, commercial, and Marketplace permissions
   separately.
2. Freeze source artifacts and evidence read-only. Maintain private source
   identity, observations, uncertainty, and rights records.
3. Transform `source observation -> abstract requirement -> product-selected
   requirement`. Give production only sanitized contracts, opaque IDs, and
   approved neutral infrastructure.
4. Select a coherent vertical slice and shared runtime interfaces. Prefer a
   small dependency closure over feature count.
5. Launch actual authoring and every repair through the frozen clean-room
   process boundary. Require reusable platform qualification and a minimal activation attestation.
6. Author, build, and freeze exact candidate bytes without dispatching a broad
   worker-local validation suite.
7. Run one `PRE_BDS_MILESTONE` job immediately before first BDS. Run BDS and
   implementation/integration work, then run one `FINAL_MOD_MILESTONE` job
   containing observation, T10, persistence, lineage, and bundle checks.
8. Route only proven product defects to one consolidated repair for generation
   `N+1`. Repair missing evidence or infrastructure without changing product
   generation.
9. Register qualified slices separately from integration, client/platform
   qualification, Marketplace approval, and release.
10. At campaign closure, reconcile every source declaration and product role,
    run the frozen portfolio audit, and assemble a slim immutable handoff.

## Non-negotiable rules

- Recompute hashes before every gate; bind evidence to the complete
  candidate/runtime/fixture/collector tuple.
- Never amend a frozen candidate, retry unchanged bytes, reveal private oracle
  cases to production, or let a worker obtain downstream PASS.
- Separate candidate-only BDS baseline from observer, GameTest,
  SimulatedPlayer, protocol-client, or direct-hook lanes.
- Compare behavior contracts with typed semantic modes. Structural JSON
  inequality alone is not a defect, and absent evidence is not false.
- A build, schema pass, clean boot, direct module test, or internal harness does
  not prove normal player reachability or client delivery.
- Require a public acquisition/trigger-to-result trace for every promoted
  player-facing feature.
- Keep authenticated identity, desktop UI/rendering/audio, controller, Realms,
  split-screen, Marketplace, and physical PS4 as separately owned gates.
- Fail closed on rights, authority, lineage, isolation, or hash ambiguity.

## Report narrowly

Distinguish evidence recorded, intent distilled, contract sanitized,
implemented, mechanically admitted, BDS qualified, semantically qualified,
slice qualified, integrated, desktop verified, and PS4 verified. Report exact
hashes, receipts, failed/blocked/untested gates, deferred scope, and the next
mechanically eligible action.
